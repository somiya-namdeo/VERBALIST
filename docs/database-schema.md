# Database Schema Documentation

## 1. Purpose of each table

- **`products`**: Stores catalog data for available products, including prices, quantities, categories, and specific tags (organic, sale).
- **`shopping_list_items`**: Manages items currently in a user's shopping list. Supports statuses like 'active', 'completed', and 'removed'.
- **`shopping_history`**: Records historical purchases made by users, providing the data needed for frequency analysis and recommendations.
- **`user_preferences`**: Contains user-level settings like dietary preferences, favored brands, and categories to personalize interactions.
- **`product_substitutes`**: Defines relationships between products to suggest alternatives when a primary product is unavailable or upon user request.
- **`seasonal_products`**: Associates products with specific seasons and regions to boost their priority during relevant times of the year.

## 2. Important relationships

- The user-specific tables (`shopping_list_items`, `shopping_history`, `user_preferences`) link directly to `auth.users`, bridging application data with Supabase's authentication system.
- All user-specific tables reference `products(id)` to map user intents (lists, history) to catalog entities. Cascading deletes ensure data integrity if a product is removed.
- `product_substitutes` has two foreign keys back to `products`, creating a self-referencing relationship with constraints to avoid duplicate mappings or self-substitution.

## 3. Why the schema supports the assessment requirements

This schema enables an agentic voice shopping assistant by establishing a foundation for structured product data, user state (shopping lists), personalized context (preferences, history), and intelligent recommendations (substitutes, seasonality). It deliberately excludes over-engineered components like NLP command logs or LLM embeddings, focusing strictly on required core functionality at this stage.

## 4. Which data will eventually come from public datasets

- **`products`**: Catalog items, including descriptions, standardized categories, brand info, and base prices.
- **`product_substitutes`**: General market knowledge of interchangeable goods.
- **`seasonal_products`**: Common regional mappings for seasonal produce/goods.

## 5. Which data will be generated by the application

- **`shopping_list_items`**: State managed via user interactions (voice commands mapping to list additions).
- **`shopping_history`**: Accumulated over time as lists are checked out or completed.
- **`user_preferences`**: Learned dynamically from interaction or explicitly set by the user.

## 6. How shopping history will support recommendations

By tracking exactly what, how much, and when a user purchases (`purchased_at`), the AI agent will eventually be able to identify reorder patterns (e.g., buying milk every week) and suggest repurchasing items proactively before they run out.

## 7. How substitutes and seasonality are represented

- **Substitutes**: Modeled as an explicit association table mapping an unavailable product to an alternative, ordered by an integer `priority`.
- **Seasonality**: Explicitly tags products with text-based seasons and regional constraints, also ordered by `priority`, allowing the application logic to filter or boost these items during seasonal searches.
